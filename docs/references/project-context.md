# Project Context

**Lazy load only** for boundary disputes or `project_context query` with `decision_count > 0`. Session routing is `npm run goal:next`, which never preloads this decision graph. Commands: `docs/workflows/validation.md`.

`script/project_context.sh` prefers `uv`, then an explicitly configured
`PROJECT_CONTEXT_PYTHON`, Python 3.13/3.12, the Codex bundled Python, and finally
`python3` only when it satisfies the package's Python 3.12+ contract. It fails with
a one-line remediation instead of emitting an incompatible-runtime traceback.

## Boundaries

- SwiftUI natives + Node HTTP API; production persistence Neon/Postgres via `DATABASE_URL`; local dev uses `data/` or `LIKEMINDED_DB_DIR`.
- TestFlight path: authenticated `/v1/*` MVP routes — not legacy mock/profile routes.
- Universal iOS/macOS bundle `com.gurusharan.likeminded`; Apple team `9UPQL479Z5`; App Store Connect Apple ID `6792839764`; shared `LIKEMINDED_API_BASE_URL`.
- Exported TestFlight apps pass `npm run verify:release-candidate -- ios|macos <app>`; the platform-specific embedded profile and signed entitlements, exact per-platform OAuth callback, production URL, privacy manifest, linked AppIcon resources, and disabled `get-task-allow` (false on iOS, false or absent on macOS) are artifact truth.
- Auth: Apple + Google + wallet on both natives (`Sources/Shared/`); sessions via Keychain (`AuthSessionStore` / `MacAuthSessionStore`).
- LiveKit group meets: `POST /v1/meetings/:id/join` + `Sources/Shared/LiveKitMeetSession.swift` on iOS and macOS.
- iOS validation routing keeps logical screen IDs aligned with their deep-link launch arguments; route details live in `docs/workflows/validation.md`.
- Explicit session handoffs use `session:stamp -- --screen <id> --platform ios|macos` so a mixed dirty worktree cannot route the next agent to the wrong native platform; related iOS screen captures use one `verify:ios-screens -- <id>…` batch build. Within one unchanged targeted-proof band, `LIKEMINDED_REUSE_IOS_INSTALL=1` skips reinstall only after the proof owner validates source freshness plus the exact built/installed executable hash for the explicit simulator and bundle. `validation/idb_ctl.sh` carries the same explicit `IDB_UDID` into its `simctl` screenshot fallback; `booted` is not an acceptable capture target.
- Concept lookup is screen-specific. Circle-placement concepts may route only circle/community surfaces; all other screens fall back to their ledger-owned `mockup_ref` instead of borrowing an unrelated concept.
- Gap-flow ownership is `validation/screens/*.json` plus `validation/gap-flows-registry.json`; scripted proof must target only the live control IDs, and destination flows require explicit outcome assertions rather than dispatch success or generic screen stamping.
- iOS `computer-use` flows require explicit `testing_ledger_prove_ios.sh` branches plus failure-enforced closeout routing. AX text matching normalizes Unicode whitespace so the Simulator's non-breaking-space `Apple Account Verification` label resolves to its tappable `Not Now` button. The locked one-screen capture route applies the same normalized-alert boundary before writing its PNG and fails closed when the alert remains, so a successful capture cannot retain system-alert chrome as visual evidence. Profile-edit snapshot capture does not stamp its interactive actions: typed update requires persisted text, voice update commits its debug-preview summary through the profile API and requires the same summary after relaunch/refetch plus a separate fail-closed live-start state, and return requires the Profile destination. A match is present only when its positive frame intersects the Application frame; hidden/offscreen matches are valid absence, and inventory errors never count as absence. Readiness and unresolved/post-dispatch failures write PNG plus AX JSON diagnostics, and a dispatched tap is never replayed through another fallback. Chat call headers wait on the accessible chat body, then use normalized identifier/label lookup plus explicit fixed-simulator toolbar points when IDB omits the visible SwiftUI navigation bar. Because this simulator drops the SwiftUI sheet identifiers from AX, each open and shared-`call-sheet-done` dismissal assertion uses the same unique, AX-exposed sheet-body marker (`Scheduling a voice call`, `Scheduling a video call`, or `Mutual match from`) and requires three consecutive valid absences; the persistent `Voice call`/`Video call` toolbar labels and background chat content are not return signals. After normal and grace polling, one durable screenshot refresh plus the measured one-second AX settle may cross the observed IDB cache boundary; five refreshed samples persist their match fields/frames, reset on visible presence, and pass only on three consecutive valid absences. All six interactions plus an unobstructed success capture must pass before any of the four controls are stamped. The proof process returns zero exactly when `flow_fail=0` and uses an explicit nonzero failure branch.
- Creation-form proofs follow the rendered disclosure sequence: Create Community expands `Add themes (optional)` before testing `Community themes`, while submit proves that name and summary alone enable creation.
- Clean-session iOS proof startup backgrounds an `exec`-owned validation API with closed stdin and redirected logs; the enclosing proof must return immediately to its health poll rather than wait on the long-running server.
- iOS Community Detail requires a confirmation boundary before leaving: the proof opens `Leave this community?`, confirms with the destructive `Leave` action, and then observes `Join community`.
- The iOS community roster is private to members: nonmembers see a join requirement, and `view-members` must establish membership before proving roster navigation.
- The iOS Community Detail tab proof deep-links to seeded `jazz-music`, scrolls until the tab row is visible, and accepts the flow only after each tab exposes its distinct content marker; a successful capture stamps the four tab controls together.
- Circle-detail options readiness is the stable `circle-detail-back` AX identifier, not presentation copy. The shared probe recognizes both `AXIdentifier` and IDB's `AXUniqueId` field so a captured identifier cannot be misreported as absent, and harness-class packets route to the platform proof script instead of product source. A genuine readiness miss must retain both PNG and AX JSON diagnostics before the flow fails.
- Targeted `testing:ledger-run` may reselect a clean pass for a matching `retest_ready` issue or an explicit operator-requested exact-target `--reprove`; the latter requires both `--screen` and `--flow` and never changes untargeted queue selection. An ineligible requested target exits nonzero with an exact recovery hint. A zero retest resolves every `retest_ready` packet matching the runner-selected platform/screen/flow (including untargeted queue runs) with the proof-log path; `npm run test:testing-ledger` guards selected-target matching and unrelated-packet preservation. Full child output stays in the proof log; default terminal output is bounded and `--verbose` opts into replay.
- Coverage history remains in the existing screen ledger: `ledger:brief -- --platform <p>` reports compact debt, while `--all --json` exposes every applicable flow's last-tested time and tested/current source hashes. Equal-priority proof selection is never-tested/oldest-tested first.
- `verify:testing-ledger` is the sole testing-integrity gate and runs from `npm run check`; it validates active route prose, the ledger contract, migration, and progress. `session-orchestrate` may retain only the bounded `ledger:brief -- --receipt` fingerprint/scalar-debt projection and next owner command, refreshing at declared source/goal invalidators rather than per flow.
- Circle Detail proof is flow-explicit: generic macOS screen capture never clicks or stamps its controls; display-only outcomes remain non-navigation, authored concern proof requires exact API readback, tabs/share prove truthful rendered and pasteboard content, and secondary selection must reopen into `About this circle` with selected state preserved. The source-card `Your second circle` value, dispatch success, compile success, or transient status copy is insufficient.
- Profile evidence scope is explicit: voice-informed signals are interview/activity inferences, not diagnosis; placement reasons explain the circle decision and are not proof for each signal. Review, re-interview, and Done navigation belong to exact flow branches.
- Soulmate is a truthful mutual-match MVP: the weekly introduction and empty/pending states come from authenticated status/matches, cards explain mutual choice after a meetup, `Keep for later` must preserve and restore the same named person, detail has no Pass or compatibility score, and Message must open the exact selected match thread. Refresh/feed controls do not belong on the destination.
- Generic macOS routes for Profile, Profile Signals, Soulmate roster/detail, and Soulmate settings are snapshot-only. Exact branches own behavior and API persistence; responsive visual proof covers 1120×901, 1200×760, and 1440×900.
- Obsolete flow removal is atomic across live UI, screen ledger, gap registry, and proof routing; append-only test issues close as `resolved`, not `retest_ready`.
- Circles are placement-first: the old `browse-expand` controls are removed; placed users see AI secondary suggestions and all remaining read-only Circle types.
- XcodeGen owner: `apps/ios-macos/project.yml` — never hand-edit `.xcodeproj`.
- macOS runtime proof owns the canonical `.build/macos` binary; the launch route rebuilds when LikemindedMac/Shared sources are newer. Same-name apps from other worktrees are invalid Computer targets.
- Testing-ledger runtime locks are PID-owned. Cross-command macOS Computer bands use `lease-acquire` and matching tokenized `lease-release`; the helper may clear a stale dead PID but never replaces a live platform owner.
- Cross-platform validation `acquire`/`release` pairs are keyed by their caller session; `with_lock` remains the preferred one-command owner.
- macOS native interaction uses bundled `@Computer` and targets the canonical validation app by full path. Shared display names and bundle IDs are ambiguous across local builds; missing windows or identity mismatches stop proof.
- A same-screen Computer band holds one bounded testing-ledger lease, keeps one canonical app instance, and stops after one repeated readiness failure rather than entering a retry loop.
- Computer flow proof resolves controls from fresh semantic state for both readiness and action targeting; cached or capped snapshots are not substitutes.
- State-changing Computer flows assert the resulting semantic and persisted state. Nested Community Detail destinations remain separate flows, and failures retain one screenshot plus compact state evidence.
- Testing-ledger child proof output is persisted per platform/screen/flow under `output/validation/testing-ledger/`; issue packets use the retained failing stage when the interactive terminal detaches.
- `ledger:screen --section route` is the compact one-screen entry: source files, entry points, UI state, and effective current/stale flow results without loading controls or full proof packets. Before full screen-family reproof, freeze flow outcomes, prove the branch requires authoritative readback and hashes every behavioral owner, run targeted proof, batch known P0–P2 fixes, then create one immutable `output/validation/acceptance/<source-hash>/` packet. JSON ledger reports must flush their complete payload before exit; truncation is a harness failure.
- Community-members validation and Computer proof use the readable seeded `ai-builders` roster and truthful neutral member rows. `jazz-music` remains the nonmember privacy-boundary fixture; circle ids are not valid community roster fixtures, and synthetic presence/gender labels are not accepted proof.
- Soulmate post-meet selection is explicit opt-in: no fixture or live row starts selected, confirmation copy states the selected count, and Computer persistence proof begins with one deliberate row tap.
- Meet-to-recap proof treats off-screen AX nodes as non-actionable and scrolls `past-row` into a viewport-safe frame before tapping.
- Profile Edit and Profile Signals validation routes push the production `ProfileRoute` destinations from the signed-in Profile root; validation does not maintain parallel screen implementations. - Parenthesized Swift source hints in screen ledgers bind hashing to the matching type declaration rather than the first call-site mention, so edits inside an owned screen cannot retain a stale `source_hash`.
- A single flow owner keeps proof, same-flow diagnosis, coherent fix, and full-retest context. `testing:ledger-fix-run -- --platform <platform> --issue-id <id>` claims the filed issue without reordering the append-only queue; the owner releases runtime locks while editing. - `script/run_validation_api.sh` reuses a healthy `:8787` validation-db listener instead of killing it; `LIKEMINDED_FORCE_API_RESTART=1` forces replace.
